# CROWN DEFENDER — Game Design Document (GDD v0.1)

## 1. Vision and design pillars

A tactile, quick-session 2D arcade roguelite built for an Apple Watch, not a reduced phone game. The player protects a fixed central reactor from enemies approaching from the perimeter. The Digital Crown is the **only required in-app input**: rotate to aim continuously; shooting happens automatically.

**Pillars:** (1) immediate and legible 360-degree aiming, (2) difficult but fair 3–5 minute runs, (3) genuinely different upgrade builds, (4) no touch controls and no side-button interception, (5) reliable offline play.

**Non-goals for v0.1:** multiplayer, 3D, advertisements, server accounts, external LLM, demanding background execution, iPhone companion, downloaded copyrighted music/art.

## 2. Full game state flow

Launch -> MAIN_MENU -> INTRO_TUTORIAL (first run only) -> WAVE_1 -> UPGRADE_1 -> WAVE_2 -> UPGRADE_2 -> WAVE_3 -> UPGRADE_3 -> WAVE_4 -> BOSS -> RESULTS -> RETRY or MENU.

- DEFEAT can interrupt any combat state if core HP reaches zero.
- INACTIVE_PAUSE is a lifecycle overlay, not a destructive restart. On resume, present Crown-selectable RESUME / END RUN.
- Every menu starts **disarmed**. The player first has to turn Crown by at least one selection step; only then can an idle dwell of 1.0 s confirm. Highlight + ring countdown must be visible.
- Never interpret a Crown focus-reset or scene transition's initial value as a deliberate selection.
- During combat Crown idle changes nothing; aim remains wherever it was.

## 3. Exact control rules

### Combat (continuous)
- Physical rotation CW -> bearing increases; CCW -> bearing decreases. Provide invert-axis option.
- Accumulate relative rotation delta from SwiftUI rotation input. Aim wraps modulo 2π and stays stable across turns.
- Turret stays at reactor center. Weapon fires every 0.40 s along barrel bearing without tapping.
- No on-screen joystick, fire, pause or inventory controls required.
- Avoid heavily smoothed aim: keep latency perceptually one frame, no input inertia by default.

### Menus (discrete)
- Every 1 virtual crown-selection-step changes highlighted choice by 1, wrapping around choices.
- On genuine rotation, reset 1.0 s dwell timer; draw countdown ring around selected choice.
- If Crown moves during dwell, cancel and restart countdown.
- On first entering menu, require meaningful deliberate movement before enabling dwell.
- Confirm at dwell expiry only once and ignore further events during transition.
- A neutral first-run tutorial explicitly explains rotate + wait, without requiring a tap.

### Optional accessibility
- Respect system accessibility where possible; never rely on color alone. An alternative touch affordance may be offered later for accessibility, but never make it mandatory for core gameplay.

## 4. Arena and baseline numerical balance

World space uses normalized arena radius R=1.0 with turret at (0,0). Render scale maps world to watch-safe playable area.

| Parameter | Prototype default | Notes |
|---|---:|---|
| Reactor HP | 5 | No negative HP; defeat at 0 |
| Reactor hit radius | 0.12 R | Damage when enemies reach it |
| Enemy spawn ring | 0.90 R | Random angle, not overlapping immediately |
| Drone speed | 0.16 R/s | ~4.9 s travel to reactor edge |
| Bullet speed | 1.40 R/s | Deterministic constant-speed physics |
| Bullet damage | 1 | Drone = 1 HP |
| Bullet collision radius | 0.035 R | Tune after physical watch tests |
| Base fire interval | 0.40 s | 2.5 shots/s |
| Starting spawn interval | 1.75 s | Wave budget further caps total count |
| Concurrent enemy cap | 12 | Include split children |
| Reactor hit invulnerability | 0.35 s | Avoid simultaneous rapid HP loss |
| Menu dwell | 1.0 s | Require user rotation first |
| Simulation timestep | Fixed 1/60 s | Accumulator + bounded catch-up |
| Target frame rate | >=30 sustained on SE2 | 60 only if measured |

Spawn positions are generated by seeded RNG; waves use a spawn budget rather than spawning forever. Collision order must be deterministic under the same input/tick sequence. Enemy reaching core despawns and deals at most one core hit.

## 5. Waves and run timing

| Section | Target duration | Content |
|---|---:|---|
| Initial tutorial | 8 s max for first run | Safe enemy, aiming demonstration |
| Wave 1 | 40 s | Drones only, light density |
| Upgrade 1 | player-paced | 3 Crown-selectable cards |
| Wave 2 | 45 s | Drone + Spinner |
| Upgrade 2 | player-paced | Different eligible choices |
| Wave 3 | 45 s | Spinner + Sprinter |
| Upgrade 3 | player-paced | Synergy decision |
| Wave 4 | 45 s | Mixed fast/slow enemies, max cap |
| Boss | 40–60 s | The Warden two phases |
| Results | player-paced | Score, best, streak, unlock progress |

Wave clock is active simulation time (pause excluded). When duration expires, stop spawning; end wave once all live enemies are cleared or escaped. Add a measured post-time budget (e.g. 8 s) to avoid getting stuck on a badly positioned enemy; on timeout safely clean up without granting kills or XP. A run should be approximately 3.5–5 minutes excluding menus and interruptions.

## 6. Enemy taxonomy

| Enemy | HP | Speed | Shape | Behavior |
|---|---:|---:|---|---|
| Drone | 1 | 0.16 R/s | Coral diamond | Radial approach |
| Spinner | 2 | 0.14 R/s | Offset toothed ring | Small tangential drift while advancing |
| Sprinter | 1 | 0.24 R/s | Arrow dart | Windup flash before short acceleration |
| Carrier (stretch) | 3 | 0.09 R/s | Three hexagons | Splits into 2 drones on death; cap applies |
| Shield (later) | 3 | 0.11 R/s | Shield crescent | Reduced frontal damage; side/back weak point |

Base MVP needs Drone/Spinner/Sprinter, plus boss. Distinct silhouette must be legible without color. Define enemy collision/contact to prevent triple damage from one clustered group. Each defeated enemy grants score; score can be fixed 10/20/15 for Drone/Spinner/Sprinter, adjusted after playtest.

## 7. Boss: THE WARDEN

The Warden spawns at arena edge with conspicuous health bar, an exposed amber core, and mechanical arms. **The player cannot move the turret**, so avoid attacks whose only counterplay would be walking/dodging.

- Phase 1 (100–50% boss HP): Warden moves slowly on outer ring and charges projectile aimed toward reactor. Draw a coral charge path for at least 0.8 s. **Counterplay:** aim at and shoot a charge orb to destroy it before it reaches the reactor; alternatively shoot boss weak core to interrupt a charge at a damage threshold.
- Phase 2 (<50% HP): two successive charge orbs or rotating shield plates (not both at once initially); show telegraph and enough reaction time for Crown turning.
- Boss attacks core only when telegraphed charge projectiles reach its hit zone; one charge deals one HP subject to invulnerability cooldown.
- Limit active adds and projectiles by performance cap, never spawn lethal unavoidable attacks.
- Win when boss HP <= 0 before core HP reaches 0. Tie-breaking must be deterministic.
- Early testing should guarantee that a practiced player with no upgrades can win with accurate aiming, while upgrades significantly change difficulty.

## 8. Upgrades, eligibility and builds

3 choices per between-wave menu; exactly one chosen, for 3 selections per run. Cards are drawn from eligible pool with no duplicates within one offer. Seed RNG ensures reproducibility.

| Upgrade | Gameplay effect | Stack / guard |
|---|---|---|
| Rapid Fire | Fire interval ×0.80 | Floor 0.16 s |
| Twin Barrel | Add symmetrical ±8° projectiles | Max 3 effective lanes |
| Piercing | Bullet passes through +1 enemy | Max 2 pierces |
| Overclock | Bullet travel speed ×1.25 | Max 2 stacks |
| Shock Ring | Every 10 s knock back nearby enemies | Nonstacking, cooldown visible |
| Repair | Immediately restore 2 reactor HP | Cap at 5, exclude when HP full if other choices available |
| Armor | Block first core hit per wave | Nonstacking, reset at wave start |
| Chain Arc | Every fifth successful projectile hit arcs to closest target | Up to 2 jumps, cap chain spam |

**Synergies:** Rapid Fire + Chain Arc = faster chain triggers; Twin Barrel + Piercing = lane control; Shock Ring + Repair = survival; Overclock + Twin Barrel = spread precision. Do not add hidden multipliers before metrics support them.

At v0.1 run-based progress is the point. Optional permanent unlocks: cosmetic turret outlines, new starting weapon variants, bestiary entries. Do not sell stat boosts or create a grind barrier to winning.

## 9. Score, persistence and retry

- Score = destroyed enemies + boss award + wave clear bonus. No score for enemies cleaned up by timeout.
- Track kills, waves completed, result, run duration, selected upgrades, best score.
- Save outcome and simple preferences locally only; use versioned JSON model / Codable with migration plan.
- RETRY resets RNG seed to a new explicit seed; include a debug mode that accepts a stable seed for reproducible testing.
- Never advance simulation while app is inactive; on resume show pause overlay with no accumulated projectile/enemy movement.

## 10. Balance and player experience acceptance

- In two seconds on 40 mm screen, player can distinguish core, barrel bearing, enemy threat, reactor HP and wave.
- Most early deaths should feel explainable; no untelegraphed invulnerable threats.
- Playtest novice vs practiced users: target viable win rate ~30–60% after learning; tune from real samples rather than treating as guaranteed.
- Dwell misselection, missed Crown events, unreadable typography, overlapping particles and unavoidable boss damage are blocking defects.
- The single primary measurable interaction goal: rotate-to-aim feels responsive and accurate.
